# Explainable Speech Emotion CBM

The project studies explainable-by-design speech emotion recognition using MELD audio utterances, HuBERT speech embeddings, and a Concept Bottleneck Model (CBM). The main goal is to compare a black-box self-supervised speech baseline with an interpretable model that predicts acoustic proxy concepts before predicting emotion labels.

## Project Overview

Self-supervised speech models such as HuBERT and wav2vec 2.0 can learn strong representations from raw audio, but their predictions are usually difficult to interpret. This project addresses that limitation by introducing a concept-based explainability pipeline for speech emotion analysis.

The implemented system compares:

1. **Black-box HuBERT baseline**
   Emotion classification is performed directly from frozen HuBERT embeddings.

2. **Concept Bottleneck Model**
   HuBERT embeddings are first mapped to acoustic proxy concepts, and the final emotion prediction is made from those concepts.

3. **Oracle concept classifier**
   Emotion classification is performed using the extracted acoustic concepts directly, used as a diagnostic reference for the concept set.

The explainability analysis includes concept-level SHAP explanations, concept ablation, and targeted concept interventions.

## Dataset

The project uses the MELD dataset:

**MELD: Multimodal EmotionLines Dataset**
Dataset link: https://affective-meld.github.io/

Only the audio modality is used in this project. Video files are converted into 16 kHz WAV audio files before feature extraction.

The emotion classification task contains seven classes:

- anger
- disgust
- fear
- joy
- neutral
- sadness
- surprise

## Methodology

The pipeline follows these main steps:

1. **MELD audio preprocessing**
   - Index MELD utterances.
   - Convert available media files to 16 kHz WAV.
   - Log missing or failed conversions.

2. **HuBERT embedding extraction**
   - Use `facebook/hubert-base-ls960` as a frozen speech backbone.
   - Pool frame-level representations into utterance-level embeddings.

3. **Acoustic proxy concept extraction**
   - Extract interpretable signal-level descriptors such as:
     - duration
     - energy statistics
     - pause ratio
     - pitch/voicing proxies
     - zero-crossing rate
     - spectral centroid
     - spectral bandwidth
     - spectral rolloff
     - MFCC statistics

4. **Model training**
   - Train a black-box HuBERT classifier.
   - Train a concept predictor from HuBERT embeddings to acoustic concepts.
   - Train a CBM classifier from predicted concepts to emotion labels.
   - Train an oracle concept classifier using extracted concepts directly.

5. **Evaluation and explainability**
   - Compare predictive performance using accuracy, macro-F1, weighted-F1, precision, and recall.
   - Add a majority-class baseline.
   - Compute bootstrap confidence intervals.
   - Use SHAP to identify important concepts.
   - Perform concept ablation for faithfulness analysis.
   - Perform targeted concept interventions.

## Results

The final evaluation on the MELD test set showed the following pattern:

| Model | Accuracy | Macro-F1 | Weighted-F1 |
|---|---:|---:|---:|
| Majority neutral baseline | 0.481 | 0.093 | 0.313 |
| Black-box HuBERT | 0.271 | 0.214 | 0.306 |
| Concept Bottleneck Model | 0.234 | 0.192 | 0.263 |
| Oracle concepts | 0.222 | 0.185 | 0.254 |

The black-box HuBERT model achieves the strongest predictive performance. The CBM loses some accuracy and macro-F1 relative to the black-box model, but provides inspectable intermediate concepts and enables concept-level explanation and intervention. The majority-class baseline shows why accuracy alone is misleading for MELD: always predicting `neutral` gives high accuracy but very poor macro-F1, which is why macro-F1 is treated as the primary metric.

The most influential CBM concepts according to SHAP were mainly spectral and cepstral descriptors, including spectral centroid mean, spectral rolloff mean, spectral bandwidth mean, MFCC means, and pitch/voicing proxy statistics. Faithfulness analysis showed partial support for these explanations: ablating the top-5 SHAP concepts produced a larger performance drop than random concept ablation, though the effect was not fully consistent at other ablation sizes. Targeted concept interventions showed that modifying important concepts can change the model's prediction or alter class probabilities, demonstrating the practical value of the bottleneck representation.

## Key Findings

- HuBERT embeddings contain recoverable acoustic information.
- Concept Bottleneck Models can make speech emotion predictions more transparent.
- Acoustic proxy concepts are useful for model inspection, but they are weakly aligned with complex emotion labels in MELD.
- Audio-only emotion recognition on MELD is difficult because many labels depend on text, facial expression, speaker identity, and dialogue context.
- The black-box model performs better, while the CBM provides better interpretability.

## Limitations

- The concepts are automatically extracted acoustic proxy concepts, not human-annotated emotional or prosodic concepts.
- MELD is a multimodal conversational dataset, but this project uses only audio.
- HuBERT is used as a frozen backbone rather than being fine-tuned.
- Explanation evaluation is model-level; no human user study or speech-expert assessment is included.

## How to Run

1. Clone the repository:

```bash
git clone https://github.com/parsa-tavakoli/explainable-speech-emotion-cbm.git
cd explainable-speech-emotion-cbm
```

2. Open the notebook:

```text
xai_ver5_final_tidy.ipynb
```

3. Run the notebook in Google Colab or Jupyter.

4. If using Google Colab, mount Google Drive when prompted.

5. Set the correct project and dataset paths in the configuration cell.

6. Run all cells.

The notebook is cache-aware. If cached WAV files, acoustic concepts, or HuBERT embeddings are already available, it will reuse them instead of recomputing everything from scratch.

**Quick run option:** the notebook supports a `QUICK_RUN` flag (with a corresponding `MAX_ITEMS_PER_SPLIT` cap) for running the full pipeline end-to-end on a small subset of the data. This is useful for sanity-checking the pipeline without paying the cost of a full HuBERT extraction pass over all 13,706 utterances.

**Runtime notes:** a GPU runtime (e.g., Colab's free T4) is recommended for HuBERT embedding extraction. With cached embeddings and concepts, the remaining cells (model training, SHAP, ablation, bootstrap evaluation) run in a few minutes on CPU. A full run from raw MELD media, including audio conversion and embedding extraction for all utterances, is significantly slower and is the reason the notebook caches intermediate outputs to Google Drive.
